# CO-POKER · 德扑

2～5 人在浏览器里合作猜牌力，通过争抢 1～N 号硬币排出先弱后强的顺序。1 号对应最强牌，累计三局成功获胜。无需账号。

公网入口：[http://101.132.136.52/](http://101.132.136.52/)  
规则与验收基准：[GAME_SPEC.md](GAME_SPEC.md)

## 本地运行

安装 Node.js 和 npm，在项目目录运行：

```sh
npm ci
npm test
npm start
```

访问 [http://127.0.0.1:3000/](http://127.0.0.1:3000/)。请通过 HTTP 服务访问，不要直接双击 `public/index.html`。服务支持 `HOST` 和 `PORT` 环境变量；健康检查为 `/health`。

用两个浏览器标签页设置不同昵称：一方“创建房间”，另一方通过房间号加入，由房主开始。完成四轮选币后会自动揭示、比较并结算。

## 菜单和规则

主菜单提供创建房间、加入房间、设置和规则。创建房间可选 2／3 张手牌、组牌规则、历史可见性及观战席位；每轮默认无倒计时，当前没有限时选币开关。

玩法手册分为目标、流程、硬币、组牌、牌型、结算、房间七页，支持上一页／下一页、目录跳页和方向键／PageUp／PageDown。正文独立滚动，翻页后回到顶部。

音效、减少动效、演出速度和昵称保存在当前浏览器本地。音效默认关闭，减少动效初始值遵循系统偏好。

- 持币后不能直接拿公共区另一枚，先点击自己的硬币归还。
- 从硬币 N 到 1 比较，牌力应逐步变强或相等；失败也会展示完全部比较。
- 普通结算的“下一局”保留累计；三胜或三负后的“再来一场”归零。两者都需要全体玩家确认。
- 当前开局后玩家掉线或离开会结束房间，不支持身份恢复和续局；服务器重启会丢失内存房间。
- 阶段化上一局回放尚未完成；可在本局结算和最终牌桌之间切换查看。

结算顶部固定展示所有玩家最后一轮的选币顺序（N→1），每次相邻比较完整播放后，在对应两名玩家之间留下一个小型 ✓／× 标记，不另设带硬币编号的结果卡片；全部比较结束才展示本局结果。鼠标悬停标记可查看双方最大五张牌、牌型和比较原因，也支持键盘聚焦、点击固定与 Esc 收起。下一局、离桌会清空旧的比较进度及详情。

“跳过全部比较”固定在比较框外，已同意人数实时同步；全员同意后跳过全部剩余比较，最大牌组选取演出仍完整保留。“查看牌桌 / 查看结算”在同一位置切换，累计次数不变；已移除“重看比较”按钮。

## 文件结构

| 文件 | 用途 |
| --- | --- |
| `public/index.html` | 当前 Vue 主菜单与牌桌模板 |
| `public/game-client.js` | 联机快照、操作、偏好、发牌及结算演出 |
| `public/game.css` | 当前界面样式 |
| `public/tabletop-art.js` | 无外部依赖的 SVG 牌面、牌背、硬币；兼容浏览器与 CommonJS |
| `public/settlement.css`、`public/settlement-details.js` | 结算顺序带、局部结果标记、悬浮牌组详情与比较原因 |
| `public/vendor/vue.global.prod.js` | 本地 Vue 运行时 |
| `src/poker.js`、`src/game.js`、`src/server.js` | 牌型、状态机、HTTP／WebSocket 房间服务 |
| `test/` | 规则、通信、静态资源和美术模块测试 |
| `deploy/publish.ps1` | 发布预览、上传、哈希核验和备份 |

`public/app.js` 以及 `styles.css`、`animations.css`、`frame.css`、`pace.css` 等旧版样式是保留的 legacy 文件，当前入口不引用。不要把它们误当成当前界面修补，也不要未经核对直接删除。当前资源引用以 `public/index.html` 为准。

## 发布到现有服务器

在项目目录的 PowerShell 中先预览待上传文件：

```powershell
.\deploy\publish.ps1 -IncludeSource
```

确认需要发布后执行：

```powershell
.\deploy\publish.ps1 -IncludeSource -Execute
```

脚本默认使用 `101.132.136.52:22`、`root`、本机 `~/.ssh/poker_server_key`，目标目录为 `/opt/cooperative-poker`。可用 `-TargetHost`、`-KeyPath` 覆盖连接配置。没有 `-Execute` 时仅预览，不连接服务器。

执行时会运行测试，备份服务器文件并核验 SHA-256。`-IncludeSource` 包含 `src/`；服务端文件变化会重启 PM2 并清空内存房间。不传 `-IncludeSource` 时只更新 `public/`。脚本不发布依赖变更，`package.json`／锁文件不一致时需要单独处理依赖。

发布后检查公网首页、`/health` 和实际双客户端牌局。健康检查仅证明进程响应，不能代替创建房间、四轮抢币、结算和续局验证。
